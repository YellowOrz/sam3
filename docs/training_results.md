### 评估与次日上午的决策

1. 有条件时，先在固定验证子集上评估未训练的文本特征（epoch 0），约 200–500 帧，跨多个序列并覆盖正常、遮挡、小目标及无手帧，避免只取连续相邻帧。记录有手帧二值 mask IoU/Dice（漏检计零）、有手帧漏检率和无手帧误检率；各候选使用同一数据和推理阈值。这些像素指标和 epoch 0 评估需要单独执行，当前训练入口不会自动记录。
2. 若今晚来不及补充像素评估，先保留每轮快照、验证标量和图像，次日上午筛选候选后做 GT 评估。少量固定验证图只用于定性检查，不能代表整个验证集。
3. 次日上午若实际分割指标仍在改善，可继续训练；若训练 loss 下降但验证 Dice loss、漏检或误检持续恶化，则停止并选择早期快照。总 loss 和 Dice 的最佳轮不一致时，两者对应快照都列为候选，最终以实际 GT 分割表现决定。没有像素指标时，soft Dice loss 走势只能作为候选筛选依据。
4. 当前 `best.pt` 仍按 `val/core_loss` 最小值保存，`learned_prompt.pt` 仍是末轮；每轮快照为 `epoch_0001.pt` 等。改变权重后，新旧 `core_loss` 不可直接比较；上文固定旧权重的 S 也不代表本轮训练目标。不要将总 loss 降低当作实际分割改善。

后续只根据本轮证据追加实验：若掩码重叠改善但无手误检明显增加，且 presence 判断变差，可只将 presence 从 5 调到 10；若实例检出稳定但重叠仍随训练下降，可只将 Dice 从 5 调到 10；若始终不如 epoch 0，先检查 GT、困难样本和阈值，不直接追加长训练。效果改善且漏检／误检稳定时，优先扩展验证序列并检查目标视频表现。新学习率微调应以选定特征作为 `initial_feature` 新开输出目录，`--resume` 会恢复旧优化器学习率。
