# 训练结果记录

本文件长期记录训练实验的配置、指标、走势、结论与下一步建议。**新实验按实验时间倒序插在旧实验前面**；同一次实验的补充分析更新原条目，并标明补充日期，保留原始结果与结论修订依据。实验时间优先使用明确的运行时间；本次采用目录名时间，不用可能受复制影响的文件修改时间。

首次分析日期：2026-09-13。范围：`outputs/train/` 中的两次训练。数据来源为各实验的 `config.yaml`、完整 `metrics.jsonl`、`best.pt` 与 `last.pt`；本次没有重新训练、运行推理或检查 TensorBoard 图像。目录外的 GT 评估未核实对应权重，不计入本次结论。

## 记录口径

- 每个实验记录：身份与目的、配置、完成状态、关键指标、训练走势、结论及后续建议。目的若未在运行配置中明确保存，应标注为根据配置推断。
- `best.pt` 按 `val/core_loss` 最小值保存；`learned_prompt.pt` 是最后一轮，并非最佳轮。下文“最佳轮”均指这个选模标准，不代表像素分割质量最佳。
- 损失越低越好；`ce_f1`、`presence_dec_acc` 越高越好。`loss_dice` 是匹配实例的 soft Dice **损失**，不能将 `1 − loss_dice` 当作全验证集二值 Dice；`ce_f1` 是检测 query 分类 F1，`presence_dec_acc` 是图片级目标存在判断准确率，均非像素准确率。
- `core_loss` 包含分项权重，并乘当前每卡 find batch 大小的平方根。训练还包含辅助及一对多输出，验证日志只有主分项，因此不能直接用训练／验证总损失的倍数判断泛化差距；每卡 batch 不同的实验也不能直接按原始总损失排名。
- 为辅助横向比较，定义验证主分项加权和 `S = 20×loss_mask + loss_dice + 5×loss_bbox + 2×loss_giou + 20×loss_ce + 20×presence_loss`，直接用日志重算，去掉显式 batch 平方根缩放。它仍受 batch 内归一化和统计方式影响，属于诊断值，不是统一推理评测结果。
- 各指标是 batch 指标的样本数加权平均；F1 并非全数据集 TP/FP/FN 汇总后的 F1。验证在每个 DDP 进程完整遍历，重复汇总不增加独立验证样本数。指标细节见 [训练说明](learned_prompt_training.md)，实现见 [训练入口](../sam3/train/learned_prompt.py) 与 [损失实现](../sam3/train/loss/sam3_loss.py)。未保存的历史代码版本不能由当前实现替代证明。
- 当前材料没有 epoch 0 基线、像素 IoU／二值 Dice、独立测试集成绩或视频遮挡恢复评测，不能据此宣称优于原始 SAM3 或已改善视频效果。

## 2026-09-11 23:50 — 随机初始化，32 个有效 token

### 训练走势与解释

1. **第 1–10 轮有明确优化进展。** 总损失下降，分类 F1 从 0 上升至 0.361270，presence 准确率从 0.612637 上升至 0.848214。首轮 F1 为 0 仅表示该阈值和匹配口径下没有有效 F1，不能据此断定所有预测掩码为空。
2. **不同目标的最佳时点不一致。** soft Dice loss 在第 **7** 轮最低，为 **0.087117**；总损失和 presence loss 则在第 **10** 轮最低。按总损失保存的特征不一定最适合最终掩码指标。
3. **第 10–30 轮出现泛化退化迹象。** 训练总损失从 99.223360 继续下降到 83.032929，验证总损失却回升。验证 mask focal、框损失仍下降，而 soft Dice loss 从 0.088256 升至 0.099971，说明优化不同分项存在分歧。是否表现为掩码变小、漏分或边界问题，需要图像／像素评估，日志不足以定位。
4. **总损失回升主要来自 presence。** 第 10→30 轮，S 增加 0.840184，其中加权 presence 增加 0.870129，其他分项合计略有抵消。最佳轮 presence 占 S 的约 **87.71%**。presence 准确率基本停在约 85%，损失仍升高，与概率置信度恶化相容，但缺少概率分布和正负样本统计，不能直接认定具体原因。

### 结论与后续建议

训练在自身验证损失口径下有效，但继续跑到 30 轮没有改善选模目标。当前优先使用本实验的 **`best.pt`（第 10 轮）**，而非末轮特征；应通过实际 GT 分割评估确认其任务效果。

本次 token 数与初始化同时改变，且每卡 batch 也不同，无法把差异单独归因于“随机初始化”或“更多 token”。下一轮优先做随机 **4-token** 与文本 **4-token** 的对照，固定每卡 batch、GPU 数、数据划分和训练预算；若要判断 token 数作用，再对照随机 4-token 与随机 32-token。

先评估已有最佳与末轮特征，确认选模指标是否匹配任务；随后再考虑早停或较低学习率。不要仅因 presence 占比大就立即改权重，应先检查正负样本及漏检／误检。第 7 轮没有编号快照，可用现存第 6、8 轮快照检查附近的 Dice 表现，不能声称已保存第 7 轮精确特征。

### 训练走势与解释

1. **第 1–5 轮总损失改善以 presence 为主。** presence loss 从 0.212617 降至 0.167274，框和 mask focal loss 也下降；但 soft Dice loss 从 0.084727 升至 0.086954，分类 F1 从 0.383187 降至 0.344207。总损失改善不能等同于各方面分割质量同步提升。
2. **soft Dice 的最佳值已在首轮出现。** 全部 30 轮中最低 `val/loss_dice` 为第 1 轮的 **0.084727**，最高 `val/ce_f1` 也出现在第 1 轮。没有训练前 epoch 0 评估，不能判断相对原始文本提示究竟提升或退化了多少。
3. **第 5–30 轮出现泛化退化迹象。** 训练总损失从 95.887519 降到 68.527583，验证总损失却从 9.357710 升到 11.986995。mask focal loss 持续改善，soft Dice loss 则总体恶化至 0.102087，需检查是否存在前景重叠质量与损失目标不一致的问题。
4. **后期回升同样由 presence 主导。** 第 5→30 轮，S 增加 1.073226，其中加权 presence 增加 1.089433。最佳轮 presence 占 S 约 **87.57%**。presence 准确率从 0.833448 升至 0.852679，却未阻止其损失增加，表明阈值准确率不足以描述概率预测质量。

### 结论与后续建议

本实验可确认早期验证总损失改善、后期继续优化训练目标却损害验证总损失。当前优先使用 **`best.pt`（第 5 轮）**；不能用第 30 轮训练损失更低作为替换理由。第 1 轮没有编号快照，无法直接从现有快照取出该轮精确特征。

下一次训练补充未训练文本初始化特征的 epoch 0 基线，并在同一独立 GT 集上比较原始文本提示、未训练特征、本次最佳特征与末轮特征。记录像素 IoU／二值 Dice、正负样本分开统计的漏检和误检；视频任务另外评估时序稳定性及遮挡恢复。完成这些评估后，再决定是否更换选模指标或调整训练损失。

若继续沿用当前验证总损失选模，应优先评估早停，避免固定训练 30 轮的额外成本；当前单次实验的第 5 轮最优不应直接写死为后续训练轮数。
