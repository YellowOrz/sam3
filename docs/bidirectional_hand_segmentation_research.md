# SAM 3 手部分割的双向记忆融合研究方案

> 初稿调研日期：2026-09-04；方案修订日期：2026-09-05。
>
> 目标：提升 `left hand` / `right hand` 在手物交互视频中的身份正确性、时序稳定性和掩码质量；严格零训练、离线处理；不训练、不微调 SAM3，也不新增需要训练的融合模块。WiLoR 仅作为可能出错的弱证据；接触物体分割保留为 TODO。
>
> 状态：已实现零训练双向 memory 读取、全序列与独立/重叠分块调度；真实 CUDA 视频精度仍待验证。跨块可信锚点、自动修复等后续研究项尚未实现。

## 1. 研究主线与已确认的设计

研究主线改为：**正反向独立构建记忆库 → 当前帧联合读取两侧记忆 → 单次最终掩码解码**。最终输出不由正反向 mask 的并集、平均或 Viterbi 选择产生。

原方案研究“两个结果中应该选哪个”；新方案研究“当前帧应该读取哪些过去与未来的记忆，才能得到更可靠的新预测”。两者可以使用相同的初始双向传播结果，但融合发生的位置不同。

已确认的起点：

1. 正反向建库阶段使用隔离的状态；将同一目标手的空间 memory、object pointer、原始帧索引和质量信息分别保存。
2. 解码当前帧时，联合读取正向库中的过去记忆与反向库中的未来记忆；先对齐实例身份，并控制总记忆预算。
3. 首版融合阶段冻结两个源库，不把最终 mask 写回源库，避免循环依赖和处理顺序造成的额外影响。
4. 固定 SAM3 全部权重；只调整推理时的记忆选择、联合读取和调度，不增加训练阶段。
5. 全序列与分块是两种调度方式，不是“结果融合”和“记忆融合”的区别。两种调度均可采用同一个 memory 融合算子，谁更好由实验判断。

核心假设是：同一目标在遮挡前后可能有互补的可信记忆，联合读取有机会纠正单方向的漂移。该收益尚未验证；共同错误、错误身份与冗余记忆也可能使融合变差。

## 2. 术语、任务边界与推理流程

### 2.1 双向建库不等于结果融合

设原视频为 `I_0, ..., I_(T-1)`，目标是指定左手或右手的一条实例轨迹。

```text
正向：I_0 → ... → I_(T-1)  → 独立源库 B_forward
反向：I_(T-1) → ... → I_0  → 独立源库 B_backward

当前帧 I_t 的图像特征
    + B_forward 中 s < t 的选中记忆
    + B_backward 中 s > t 的选中记忆
    → 联合 memory attention → mask decoder → 最终 mask Y_t
```

上述图示假设两端存在可用初始化。若端点不可见或检测失败，应记录失败或使用预先规定的可信锚点协议，不能把错误的端点 mask 当成可靠提示。中间锚点向两侧扩展也必须明确各自覆盖范围。

建库仍需要方向内的中间 mask：SAM3 的 memory encoder 将图像特征与预测 mask 编码成空间记忆。“不在结果层融合”不等于取消这些中间预测；它们用于建库与诊断，最终 mask 由联合 memory 重新解码得到。

首版排除当前帧自身的方向内 memory，避免直接把该帧中间预测作为它自己的记忆证据。人工或固定视觉提示帧应单列提示协议，并将提示帧与未提示帧分别评估。

### 2.2 状态、方向与身份

正反向不得共用会被同一 `frame_idx` 覆盖的输出字典。物理倒序索引必须映射回原时间轴，object ID 也必须先关联为同一目标身份。不能以“两边都叫 ID 1”作为匹配依据，更不能将全部非零 label 合并后作为目标手 memory。

物理反转视频与 `propagation_direction="backward"` 的等价性需要验证；后者只是遍历方向，不是双向 memory 融合开关。避免反复有损视频编码对输入造成额外差异。

还要区分两种反向初始化：

- 后侧独立检测或独立提示产生锚点：提供新的观测依据，但检测仍可能与正向共同出错。
- 正向末帧预测作为反向锚点：可用于往返细化，但依赖正向结果，不能声称两路是独立证据。

所有比较均报告提示来源、数量、位置，以及自动检测调用次数。

### 2.3 三阶段成本

推荐方法包含正向建库、反向建库和融合解码三个阶段。可共享静态图像特征来减少重复 backbone 计算，但不能把整体成本描述为仅两遍推理。离线版本允许读取未来帧，不满足严格实时因果约束。

## 3. 为什么方向不同，以及长传播是否必要

SAM3 tracker 根据已处理帧的预测生成并筛选记忆。初始化差异、遮挡、手物粘连、另一只手干扰，以及错误预测的递归写入，均可造成方向差异。正反向一致只表示一致，不保证身份或边界正确。

**连续传播整段视频不等于每帧 attention 读取全部历史。** 当前 tracker 已限制和筛选参与读取的普通空间记忆与 object pointers；提示帧另有选择策略。不过，有限数量的记忆也可能来自长时间传播形成的预测，仍存在间接的长期依赖和错误累积。

因此必须分别讨论：

- 传播依赖可以跨多远；
- 每帧实际读取多少 memory tokens；
- 实现保留多少中间缓存，以及何时能够输出结果。

将三者混在一起，会错误地推导出“全序列必然 attention 很贵”或“分块必然消除漂移”。

## 4. 全序列与分块：正式研究变量

### 4.1 如何回答“为什么不分块，每块先正向再反向”

可以直接回答：

> 分块是合理方案，目前没有证据说明必须从头到尾连续传播。最初采用全序列，是为了先建立不受人为块边界影响的双向基线，并保留跨遮挡区间的信息传递路径；它不是预设最优解。分块能够限制局部处理范围，但如果每块清空记忆，就可能丢失跨块身份和遮挡前后的清晰参照。因此我会在相同记忆和提示预算下比较全序列、独立分块，以及保留少量可信跨块记忆的分块方案，判断任务真正需要多长的时序上下文。

其中“保留信息传递路径”不保证有用记忆一直被保存或成功读取。是否真的提升长期遮挡恢复，必须通过数据证明。

### 4.2 三种调度方式

| 调度 | 块间状态 | 潜在收益 | 主要代价或风险 |
|---|---|---|---|
| 全序列双向建库 | 每个方向在整个视频内连续传播 | 不引入人工块边界；可利用块外的锚点与时序证据 | 错误可跨较长区间传播；全局反向完成前难以输出最终结果；建库缓存可能较大 |
| 独立块内双向 | 每块重新初始化，普通与长期记忆均不继承 | 限制跨块污染；可释放块缓存；条件满足时块间可并行 | 块内可能没有清晰目标；重复初始化；边界处身份和预测可能不连续 |
| 重叠分块 + 有限跨块可信记忆 | 局部库重建，保留筛选后的少量身份/锚点记忆 | 同时利用局部双向上下文与较远身份参照 | 继承的错误仍可传播；需要去重、门控和明确的信息可用范围 |

分块并不自动重置误差：若反向直接沿用本块正向的错误终点，或下一块继承前一块全部状态，只是改变循环结构，污染路径仍存在。真正的误差截断依赖可信重新初始化、记忆筛选或明确重置。

### 4.3 分块在哪些情况下值得优先考虑

当大部分纠错证据都在短时间邻域内，块内通常能找到清晰目标，并且需要控制缓存或输出等待时间时，局部双向处理可能更合适。重叠上下文也能让核心输出帧获得块边界两侧的邻帧证据。

但如果一个块几乎全是遮挡或模糊，可靠外观只在块外出现，完全独立分块就失去该参照。例如，假设第 90 帧开始遮挡，直到第 170 帧才清晰恢复，而切块使当前处理窗口在第 150 帧结束，则窗口内反向传播无法使用第 170 帧的清晰观测。全序列可能利用它，扩大窗口或跨块检索也可能解决；这只是说明信息范围不同，不是全序列必胜的证明。

完全遮挡时不要求输出不可见手部的轮廓；这里的恢复指重新可见后的身份与可见区域分割。

### 4.4 建议的分块实验协议

第一步使用固定长度块检验问题，不先引入复杂的自适应切块：

1. 将视频划分为互不重叠的核心输出区间；每个核心向前后扩展上下文，形成处理窗口。
2. 在窗口内隔离正反向状态建库；“先正向后反向”仅表示执行次序，不自动共享方向内状态。
3. 用两侧 memory 联合解码，只输出该窗口负责的核心帧。每帧由唯一核心区间负责，不在重叠区平均或选择多个最终 mask。
4. 先测窗口间完全独立；再测固定总 token 预算下，用少量可信跨块锚点替换部分局部记忆。
5. 对跨块记忆记录帧索引、目标身份、来源方向、可见性和质量；相同源帧/对象/来源记忆去重，不能把重叠窗口产生的重复观测当成额外独立证据。

离线跨块记忆可以来自预先构建的全局锚点库，但必须计入预扫描成本。这一方案仍是离线局部解码，不能声称具备仅等待一个块的延迟。若目标是有限前瞻，则只能使用当前窗口结束前已获得的锚点；不能偷用更远未来的信息。

建议在验证集上探索如 1、2、4、8 秒的窗口尺度，记录对应帧数与帧率，并改变切块起点，检查收益是否依赖偶然有利的边界。这些是候选实验值，不是已验证的最优参数。

### 4.5 计算量不能凭直觉判断

在每帧 memory token 数固定时，全序列三阶段与无重叠分块三阶段的主要逐帧网络工作量都近似随帧数线性增长；分块并不天然把两遍或三阶段变成一遍。质量筛选扫描与缓存管理还可能带来额外开销，需要实测。

重叠会重复处理帧；每块检测和重新初始化也有成本。分块可能降低峰值缓存、缩短结果等待时间，独立块并行也可能降低墙钟时间，但不代表总 GPU 工作量必然减少。若继承跨块状态，块间并行性还会受到依赖限制。

### 4.6 相关工作的边界

[DEVA](https://arxiv.org/abs/2309.03903) 使用双向时序传播进行半在线分割假设融合，说明双向处理不必以整段视频为唯一单位。但其融合对象和结构不等于本文提出的 SAM3 memory token 联合读取，不能直接作为本方法有效的证据。

[RMem](https://arxiv.org/abs/2406.08476) 研究了限制记忆容量、平衡信息重要性与新鲜度的价值，支持对记忆冗余保持审慎。它也不等于证明“固定分块优于连续传播”。

## 5. 双向记忆融合的技术方案

### 5.1 记忆表示和选择

对源帧 `s`、目标手 `o` 和方向 `d`，缓存：

```text
entry(s, o, d) = {
    maskmem_features, maskmem_pos_enc, obj_ptr,
    original_frame_index, object_identity, source_direction,
    conditioning_status, visibility_evidence, quality_evidence
}
```

空间 memory 与 object pointer 的选择策略都需要明示。不能只改空间 memory，却宣称所有对象记忆都已实现双向融合。质量字段保留原始量和来源，不把代理分数冒充模型内部质量。

对非提示目标帧 `t`：

```text
A_t = Select({entry(s, o, forward): s < t}, budget_past)
B_t = Select({entry(s, o, backward): s > t}, budget_future)
H_t = MemoryAttention(X_t, Spatial(A_t, B_t), Pointers(A_t, B_t), Positions)
Y_t = MaskDecoder(H_t, high_resolution_features_t, valid_prompts_t)
```

首版按受控预算为两侧分配名额，使用已有质量信号筛选；某侧没有合格记忆时允许仅用可用侧，不能为凑满配额强行加入错身份记忆。两侧都不可用时走显式的无记忆/重新检测协议，并记录状态。

### 5.2 融合位置

在 [`sam3_tracker_base.py`](../sam3/model/sam3_tracker_base.py) 的 `_prepare_memory_conditioned_features()` 中构造联合 memory tokens，调用已有 `self.transformer.encoder`，随后由 `_forward_sam_heads()` 产生一个最终预测。

联合 cross-attention 让当前图像查询两侧记忆，是第一版的融合算子；它允许输出不同于两路中间 mask 的新结果。首版不直接平均不同源帧的同坐标 memory，因为运动和形变使其未必空间对齐。

这里是待实现的内部改动，不能只在外部脚本中合并两个结果字典完成。

### 5.3 零训练的位置编码与局限

原模型的空间 memory 使用离散时间槽位编码，pointer 使用自己的相对时间编码。双向联合读取必须建立一致的原时间轴，不能让两套反向索引与正向索引混用。

零训练基线建议先以时间距离映射到已有合法槽位，并明确这是对原编码的复用，不保证模型能够显式区分过去与未来。Pointer 的符号约定、范围和单向过滤要单独核对。超出原编码范围的距离映射规则应固定并记录。

不要给冻结模型随机增加可学习方向 embedding 后声称它理解方向。若双侧读取出现方向混淆，在已有编码、记忆配额、质量阈值和窗口范围内做零训练消融；训练新编码或门控模块不在本项目范围内。

### 5.4 总预算与 token 排序

固定每帧空间 tokens、pointer tokens 和提示信息预算，比较单侧与双侧。不能把双侧记忆数量翻倍造成的收益全部归因于双向信息。

当前实现要求 object pointer tokens 放在全部空间 tokens 的末尾，并以 `num_obj_ptr_tokens` 告知 attention 的位置编码处理。应组织为：

```text
[所有选中空间 tokens ; 所有选中 object pointer tokens]
```

不能直接拼接两份 `[空间; pointer]`，否则第一份 pointer 会混在空间 tokens 中。

### 5.5 源库冻结与质量控制

最终解码阶段不调用写回源库的逻辑；同一源库快照上的帧应可独立解码。联合解码的结果和诊断另存，不覆盖正反向中间预测。

质量筛选优先复用现有 predicted IoU、presence、有效质量分数等机制。SAM3 基础路径已有 memory selection，因此“按质量选记忆”本身不能作为全新贡献；研究重点是跨方向选择、身份保持和污染控制。

低 presence 可能表达真实遮挡，而非错误记忆。应区分“目标不可见”和“跟踪不可靠”，评估可见性相关记忆的保留策略，不一律删除所有低可见性条目。

## 6. 不确定区间与可信锚点记忆补充

正反向中间 mask 的持续分歧可以用于定位可疑区间，但不用于决定最终选择哪一路。触发时还需模型质量下降、身份冲突或可靠的运动一致性异常等独立证据；两边一致地错仍需抽检。

双锚点修复改为：

1. 在可疑区间两侧寻找身份明确、外观清晰且质量有支持的可信帧。
2. 从各锚点创建隔离状态向区间内部建库；不直接把两侧 mask 做并集或稳定核心融合。
3. 从新增来源中选取可靠记忆，在同一总预算下补充或替换原有记忆，再统一解码区间。
4. 检查身份、可见性、锚点一致性和边界连续性；失败则撤销本次记忆补充并恢复原融合版本，记录复核需求。

没有可信锚点时不强行修复。锚点可以来自预先规定的单帧检测/提示协议或多证据支持的完整预测，但必须记录来源。恢复原融合版本属于修复流程的回滚，不是新的 `F/B` 结果层选择器。

## 7. WiLoR 的作用边界

WiLoR 保持为经过可靠性门控的弱证据。可利用 detection confidence、已有可靠性量、handedness 局部稳定性、wrist/MCP 轨迹突变和可见关节几何一致性来构造 `valid_wilor(t)`。

通过门控后，WiLoR 用于辅助目标身份匹配、惩罚明显属于另一只手的记忆、筛查锚点，并作为不确定性判断的辅助证据。它不能单独触发修复、决定左右手身份，或要求遮挡帧的 mask 强行覆盖预测关节。

现有 WiLoR 脚本要求正点落在上一轮目标 mask 内，主要帮助维持已有区域，不能据此假设能恢复完全漏掉的手指。主线实验先不依赖 WiLoR，再测其增量作用。

## 8. 本地实现依据与已有结果

### 8.1 源码接入与限制

| 位置 | 现有机制 | 新方法需要做的事 |
|---|---|---|
| [`sam3_tracking_predictor.py`](../sam3/model/sam3_tracking_predictor.py) | 按方向遍历、缓存帧输出 | 隔离正反向状态，导出两侧建库数据 |
| [`sam3_tracker_base.py`](../sam3/model/sam3_tracker_base.py) 的 `_prepare_memory_conditioned_features` | 按方向筛选空间 memory 与 pointers，再送 encoder | 改为预算受控的双侧读取，核对时间编码和 pointer 顺序 |
| 同文件的 `_encode_new_memory` | 将图像与预测 mask 编码入 memory | 用于源库构建；最终融合解码阶段避免写回 |
| 同文件的 `_forward_sam_heads` 调用处 | memory-conditioned 特征进入 mask decoder | 保留一个最终解码出口 |
| [`memory.py`](../sam3/model/memory.py) | mask 与图像特征形成空间 memory | 首版复用，不直接平均跨帧特征图 |
| [`model_builder.py`](../sam3/model_builder.py) | 基础 SAM3 已有时间消歧/记忆筛选配置 | 固定 checkpoint 与配置，对已有机制做受控消融 |

SAM3.1 multiplex 有不同的多对象共享记忆路径，不能直接复用标准 SAM3 patch。第一阶段固定基础 SAM3，跨版本验证放在后续。

### 8.2 分数语义

公开 `out_probs` 是实例首次检测分数，不能当逐帧 mask 质量。现有 `out_tracker_probs` 可用于诊断，但不等于同时获得纯净的 predicted IoU、presence 和模型 stability。需要从内部导出所用量并核对定义；几何 stability proxy 必须标注为代理量。

### 8.3 初稿记录的无标注审计

以下是 2026-09-04 初稿保存的历史统计，本次文档修订未重新运行数据审计：对 `outputs/test_sam3/{left,right}_hand_{forward,backward}` 中 14 组结果、8,378 帧进行前景 IoU 比较，序列均值的均值为 0.761、中位数为 0.903，6/14 序列均值低于 0.7；`IoU < 0.5` 的最长连续区间为 447 帧。

该审计合并了非零实例 label，且包含两边同时为空导致 IoU=1 的情况。它只能说明存在值得分析的方向差异，不能证明候选互补、记忆融合有效或分块优于全序列。正式评估必须先做目标实例匹配，并重查反向初始化及方向等价性。

## 9. 评估设计

### 9.1 数据与公平性

按视频、人物或采集场景划分阈值验证与最终测试，不能随机按帧切分。覆盖双手交叉、手物遮挡、运动模糊、进出画面、快速形变和长时间遮挡；同时标注高分歧和高一致区间，避免漏掉共同错误。

全序列与分块比较固定模型、输入分辨率、文本/视觉提示协议和 memory token 预算。主要受控实验使用同一组预先定义的检测/提示候选，只允许方法按其上下文范围读取；若某方法额外增加每块检测，单列为新增检测预算实验。无可用锚点的块计入失败或显式回退统计，不从测试中删除。

完整记录可访问的未来范围和预扫描成本。全序列 source bank 上限制检索窗口，只能检验“读取范围”，不能等同真正独立分块，因为 bank 本身已含跨块传播依赖。

### 9.2 必跑基线与消融

| 组别 | 比较 | 要回答的问题 |
|---|---|---|
| 结果层对照 | 原始正向、反向、历史 Viterbi、Viterbi + 保守修复 | 新方法相对于已有实现的实际价值 |
| 读取算子 | 固定同一源库：仅过去、仅未来、联合两侧 | 新增时序方向的作用 |
| 预算控制 | 相同总 tokens 的单侧/双侧；另列加倍预算 | 提升来自方向还是容量 |
| 质量控制 | 原有筛选、双向名额分配、额外身份/质量门控 | 新筛选相对于已有机制的增量 |
| 调度 | 全序列、独立分块、重叠分块、加有限跨块锚点 | 局部上下文与跨块依赖分别贡献多少 |
| 分块参数 | 多种窗口长度、重叠长度、切块起点 | 是否存在稳定且足够小的上下文尺度 |
| 锚点来源 | 独立后侧观测、前向末帧伪 mask | 新观测与往返细化的区别 |
| 编码与筛选 | 复用已有距离编码、改变记忆配额/质量阈值 | 零训练条件下如何稳定利用两侧证据 |

保留每视频和逐帧 `oracle(F,B)` 作为结果层候选选择的诊断参考。**该 oracle 只是在已有候选中选择的上限，不是 memory 融合的上限，也不能作为停止研究 memory 融合的条件。** 联合记忆解码可以产生两个原始候选都没有的 mask。

### 9.3 指标与切片

主指标为 region IoU、boundary F-score、串到另一只手/前臂/接触物的像素比例、identity-switch 次数、最差 10% 帧质量与最长失败区间。可见和完全不可见帧分开报告，同时评估目标存在性，避免空帧虚增均值。

对分块额外报告块边界附近的质量和身份跳变、块内部质量、跨块遮挡后的恢复时间、无可信锚点块的失败率。用不同边界偏移重复实验；长遮挡按其持续时间与窗口长度的关系分组。

诊断记录读取记忆的源帧、方向、质量、时间距离和实际 tokens；需要因果解释时做移除某侧记忆的消融，不能仅凭 attention 权重认定该记忆有用。

效率分别报告总 GPU 时间、墙钟时间、峰值 GPU/CPU 内存、源库存储、重复处理帧数、检测调用数、首次最终输出延迟与前瞻范围。全序列的单步 attention 工作集与全视频建库缓存分开记录。

### 9.4 成功与调度选择

在测试前固定判据：相对最佳单向和历史 Viterbi 基线获得跨视频稳定提升，身份串轨不恶化，并改善尾部失败。以视频为单位报告差异分布或置信区间，避免均值被单个 clip 主导。

若短窗口在上述指标上与全序列接近且降低实际资源/延迟，优先采用分块；若差异集中于跨块长遮挡，先测试有限可信锚点是否足够；仅在这些证据表明更长依赖确有价值时，才保留全序列为最终方案。不能预先把它称为性能上限。

## 10. 实施路线图

### P0-A：固定协议并导出源记忆

- 固定基础 SAM3 版本、提示来源、目标身份与反向初始化；复核物理倒序/API backward 等价性。
- 替换当前脚本的 Viterbi 主流程，增加独立源库导出与只读解码接口；旧结果层方法仅通过历史版本复现实验。
- 核对空间记忆、pointer、时间编码、质量量和存储成本，标注冲突与共同错误片段。

### P0-B：最小双向 memory 读取

- 在标准 tracker 的 memory 读取位置实现固定预算的双侧选择与联合 attention。
- 保留单次最终 decoder；源库冻结，不写回；先不新增 WiLoR、光流或学习模块。
- 验证退化为单侧时的数据流，检查 pointer 排序、未来索引和目标身份；完成真实视频评估。

### P0-C：全序列与分块比较

- 用同一融合算子分别运行全序列、独立分块和重叠分块。
- 固定核心输出归属，扫描窗口尺度与边界偏移，计入额外检测和重叠成本。
- 根据长遮挡和块边界失败，引入少量跨块可信锚点作为下一项受控实验。

### P1：可信记忆增强

- 加多证据不确定区间检测、双锚点建库与区间重新解码。
- 消融记忆质量/身份门控；最后再加可靠光流或 WiLoR。
- 始终冻结模型，评估不同已有时间槽位映射、记忆配额与质量筛选的收益。

### P2：仅在诊断支持时扩展

- 研究无需训练的多路径记忆、检索策略或自适应窗口，避免同时加入多个未验证模块。
- 扩展到 SAM3.1 multiplex 并重新检查共享记忆与对象身份协议。
- 融合结果递归写回单列为后续实验；它改变依赖关系和污染风险，不混入冻结源库基线。

## 13. 当前零训练实现与使用

`process_bidirectional_videos.py` 已切换为 memory 融合，移除旧 Viterbi 和结果层修复入口。其他脚本仍使用原来的 SAM3 API；模型内部只有在本脚本显式开启 capture 时才保存源记忆，不新增模型参数或修改 checkpoint 格式。

全序列：

```bash
python scripts/process_bidirectional_videos.py \
  --input-root DATA --output-root OUT_MEMORY \
  --prompt "left hand" --version sam3 --device cuda:0 \
  --checkpoint /path/to/sam3.pt --backward-mode physical
```

重叠分块：在上述命令中增加 `--chunk-frames 120 --context-frames 30`，每块负责最多 120 个核心输出帧，前后最多各加 30 帧上下文。`--context-frames 0` 为独立无重叠分块；`--chunk-frames 0` 为全序列。窗口串行处理，源记忆临时存盘并在窗口完成后释放；当前仍预先提取全视频帧并在结束时写最终视频，不能据此宣称已实现流式低延迟输出。

消融参数：

- `--memory-side both|past|future`：仅改变最终读取方向，仍固定建库协议。
- `--memory-frames 6`：空间 memory 的总帧数上限，包含条件帧；两侧分配名额，某侧不足时补充另一侧。
- `--pointer-frames 16`：object pointer 的总帧数上限。实际拆分后的 tokens 另行记录。
- `--memory-min-quality 0`：按内部 predicted IoU 筛选；默认不排除质量未知的条目。低 presence 不直接等于错误，不作为硬删除条件。
- `--min-match-iou 0.1`：双向目标实例关联的最低平均 IoU，是需要验证的保守门槛，不是已校准值。
- `--ground-truth-root GT_ROOT --ground-truth-label 1`：生成正向、反向和 memory 融合评测，另列可见/不可见帧。

默认采用物理倒序。`--backward-mode api` 可显式使用 API 反向；`verify` 额外比较两者的公开 mask 和分数，失败则停止并保存诊断。公开输出等价不代表 hidden memory 等价，因此 verify 成功时仍使用物理倒序源库，不自动改用 API 源库。

输出：

- `forward/masks.mkv`、`backward/masks.mkv`：每个核心帧所属窗口的目标实例二值 mask，不再是全部实例 label 视频。
- `masks.mkv`：统一 memory 解码的最终目标 mask。
- `result.mp4`：Forward、Backward、Memory fusion、Difference 四宫格。
- `frames.jsonl`：窗口归属、原时间轴上的空间/pointer memory 来源、质量、总 tokens、最终质量和复核状态。
- `metadata.json`：模型/参数 fingerprint、窗口及核心范围、局部身份匹配、源库大小、推理帧次、完成状态。
- `audit.json` 与可选 `evaluation.json`：方向差异和带 GT 的精度比较。F/B oracle 仅为候选选择参照。

限制：目前只支持基础 SAM3 单 GPU；其他脚本的 SAM3.1 能力不受影响。每块依据文本提示与块内双向关联确定身份，尚无跨块长期身份保证。时间编码采用已有的无符号距离编码，超出范围时截断，没有新增可学习方向 embedding。若两路身份不匹配或没有合法空间 memory（例如无上下文的单帧块），当前保守输出空 mask 并标记 `requires_review`；这是拒绝自动判断，不等于声称手不可见，不可在评测中删除这些帧。建议给短块设置上下文。

本实现覆盖 P0 核心流程。跨块可信锚点库、WiLoR/光流增强和区间自动修复仍是研究项。代码正确性测试不代表分割精度提升，必须使用真实权重和标注视频完成第 9 节实验。
